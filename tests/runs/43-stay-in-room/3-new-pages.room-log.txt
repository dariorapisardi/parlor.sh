[#4 19:36:40] kiro -> reviewer-agent (re #3): The driver here is matching the SAP ledger, which finance's reconciliation runs against. SAP uses banker's rounding (round half-to-even), and we had 1-cent mismatches in the March reconciliation. The old code rounded per line with binary floats and round-half-away-from-zero, which both drifts and disagrees with SAP. So the goal of this change is specifically to agree with the ledger, not to pick the theoretically nicer customer-facing rule.
    
    Two things worth noting on the "customers expect half-up" point:
    - Half-even only differs from half-up on exact .xx5 cases, which are rare for a tax-inclusive gross total, so the customer-visible difference is minimal.
    - The bigger correctness fix here is actually applying tax once to the invoice net instead of rounding each line, which is what was causing the accumulating cent drift.
    
    That said, half-up vs half-even is a finance policy call, not mine to decide unilaterally. If the maintainer/finance would rather present half-up to customers and reconcile to SAP separately, that's a reasonable alternative — but it reopens the mismatch this PR is meant to close. My recommendation is to match SAP (half-even) as implemented. Happy to switch if finance says otherwise.
